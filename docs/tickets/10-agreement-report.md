# 10: Agreement report

**What to build:** The methodology page shows how often the machine's suggested coding matched the coder's final coding, by period and extractor version.

**Blocked by:** 06

**Status:** done (2026-10-18, PR #14; unattended run, reading stated below)

- [x] A derived file computes, for accepted moves with suggestions, agreement on Type, Domain, Issue (and grouping where applicable), by period and extractor version. *Reading taken: the unit compared is the accepted event with a suggestion (suggestions live on events, the final coding on their move), so a move formed from several candidates counts once per candidate. `pipeline/agreement.py` → `data/agreement.json` in the build (never committed; `python -m pipeline.agreement` prints it as Markdown). Agreement on a set (Domains, Issues, dyads) is exact equality; a suggestion whose Type the extractor could not name is a Type disagreement; Grouping compares a suggested move, where the extractor proposed one, with the move the coder chose (the current extractor proposes none, so that column stays empty until one does); "All" is Type + Domains + Issues. Also per-flag suggested/final/both counts, a Type confusion matrix, and the outcome of every decided suggestion (accepted, merged as duplicate, rejected). Period = the event's calendar year (not the five-year MAVD bin; a backfilled 1974 event lands in 1974); extractor version = the `extractor` field (model and prompt hash).*
- [x] The methodology page renders the report with its definitions. *Section "How good are the machine's suggestions": definitions list, by-extractor table with outcomes, by-year table, Type confusion matrix; while nothing has been reviewed the page says so; when suggestions were decided but none accepted, the outcomes table alone shows.*
- [x] The file is regenerated by the site build; a test checks it against a fixture. *`tests/test_agreement.py`: eleven fixture events (right, wrong, nameless Type, rejected, duplicate, candidate, seed, two extractors, two years) whose every number is written by hand; the all-rejected case; the empty report; the built page carries the numbers, renders without console errors, and its empty state tracks the report whatever the data holds.*
