# 14: Extraction without an API key

**What to build:** The weekly run proposes candidates without a paid API key: the extraction step runs on the maintainer's Claude subscription through the Claude Code GitHub Action (secret `CLAUDE_CODE_OAUTH_TOKEN`), and the same prompt files can be answered in a live session when no credential is set. A relevance filter and a per-run cap keep the subscription cost small.

**Blocked by:** 07

**Status:** built (2026-10-26); the subscription route's live run awaits the `CLAUDE_CODE_OAUTH_TOKEN` secret, the waiting route runs on the next schedule without it.

**Why.** Ticket 05's live run has waited since 2026-10-15 for `ANTHROPIC_API_KEY`; the maintainer cannot fund API billing. GitHub Models, considered as a free route, was retired on 2026-07-30. The Claude Code GitHub Action accepts a subscription token (`claude setup-token`; Pro, Max, Team and Enterprise plans) and its runs "use your Claude subscription instead of API billing" (code.claude.com/docs/en/github-actions). The extraction prompt, the parsing and every check stay the pipeline's (ADR 0003 unchanged); only who answers the prompt changes, and the answerer is named in the `extractor` field so the agreement report keeps the routes apart.

- [x] `harvest prompts` writes a run's extraction prompts as files (the system prompt once, one user prompt per document, an index) and `harvest extract --recordings` consumes the answers in the recorded-response format, so prompts answered by any route yield the same candidates as a direct extraction. Seam-2 test: the fixture captures, written as prompts and answered from the fixture recordings, extract to the same `candidates.csv` as the recorded extractor. *`extract.write_prompts` / `prompt_key` (the recording key, so an answer file is a recording); `harvest prompts --captures --out [--max-documents N] [--all]`; `harvest extract --prompts DIR` restricts the run to the index's selection. An answer without token counts gives cost "unknown". Documents are cut at `MAX_DOCUMENT_CHARS` (12,000) in `user_prompt`, so the API route sees the same text (the fixtures are shorter; their recordings still match). `tests/test_prompts.py`.*
- [x] A relevance filter drops documents that name no South China Sea term or feature (gazetteer names and a multilingual term list), and `--max-documents` defers the rest, newest first; deferred documents are fetched again next run, irrelevant ones are not. Both are counted in `run.json`. *`pipeline/relevance.py`: `TERMS` (English, Vietnamese, Malay/Indonesian, Chinese; the sea, its parts, the island groups, the dispute's vocabulary, the agencies) plus every gazetteer name `usable_name` accepts, word-bounded after accent folding for Latin script, substring for CJK; `select(captures, max_documents, everything)` orders by publication date, newest first. In `extract_all` an irrelevant document is skipped and counted (`irrelevant`), a deferred one is a failure with `Extractor.DEFERRED` as its error (`deferred`), which `ops.drop_failed` already retries. The filter is loose on purpose: a wrongly kept document costs one prompt; a wrongly dropped one is lost, so the term list errs wide.*
- [x] The workflow runs without `ANTHROPIC_API_KEY`: with `CLAUDE_CODE_OAUTH_TOKEN` it answers the prompts through the Claude Code GitHub Action (a repository skill, `/harvest-extract`) and opens the review pull request as before; with neither secret it fetches and opens one "waiting for extraction" issue instead of a failure (closed by the next run that extracts). *`ROUTE` (dry | api | subscription | none) is computed once from the inputs and the secrets; `permissions` gains `id-token: write`; the action step has `continue-on-error`, so the extract step's exit code (no candidates and only failures = fail) judges the job; a run on the `none` route does not push the state, so the documents are fetched again when a credential exists (the feeds' own windows bound the backlog). The waiting issue is `ops failure-issue --kind waiting` (own label, title and marker; the next extracting run's `--resolved` closes both kinds). Not yet verified live: the action step (no token yet). Changed from the ticket text: captures are not saved by a waiting run — they are re-fetched, which is cheap and keeps the state branch small.*
- [x] The session route is documented: a maintainer (or an assistant in a session) pulls the harvest state, writes the prompts, invokes `/harvest-extract`, extracts and opens the pull request with the existing commands. *README "Extraction without an API key", the waiting issue's body, and `.claude/skills/harvest-extract/SKILL.md` (the same skill the action runs; batches of eight through subagents; a missing answer is a wasted document, never a corrupted one; the agent never runs the pipeline or commits).*

**For the maintainer.** Install Claude Code on your computer (npm: `npm install -g @anthropic-ai/claude-code`, or the installer at claude.com/claude-code), sign in with your Claude account, run `claude setup-token`, copy the token it prints, and add it as the repository secret `CLAUDE_CODE_OAUTH_TOKEN` (Settings → Secrets and variables → Actions). Then dispatch the harvest workflow once (Actions → harvest → Run workflow, dry run off) and read its summary; the review pull request it opens is the first live yield. `max_documents` is the lever on cost: 80 a run by default; the summary shows how many were deferred.
