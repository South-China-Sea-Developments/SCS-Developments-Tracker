# 08: Event map with time slider and filters

**What to build:** A visitor sees real event locations on a map, scrubs through time, and filters by claimant, Type, Domain, Issue and Dyad; named features resolve to coordinates from a committed gazetteer.

**Blocked by:** 03, 06

**Status:** done (2026-10-15, PR #9)

- [x] A committed gazetteer of South China Sea features (reefs, banks, islands, shoals; English, Chinese, Vietnamese, Filipino names) with coordinates and sub-region. *`data/reference/gazetteer.csv`: 283 features generated from Wikidata by `pipeline.gazetteer_wikidata` (every coordinate-bearing item inside the ten polygons whose type is a maritime feature; labels in en/zh/vi/tl/ms plus aliases; QID and retrieval date per row), and `gazetteer_extra.csv` with hand corrections and additions (pinyin and Filipino aliases for the most-cited features, Union Banks, Pratas, Natuna; the Spratly Islands as a whole resolve to no single sub-region). `pipeline.gazetteer` resolves a free-text location to the feature named earliest in it (longest name on a tie; Latin names on word boundaries, CJK anywhere) and finds the sub-region of any coordinate by point-in-polygon. A test checks every feature lies in the sub-region it states.*
- [x] Events with `location_precision = point` or `feature` are plotted; `subregion`-only events are shown as sub-region counts, not points. *Placed = has both coordinates; a `feature` event gets them at `queue open` (and on an edited name) when the gazetteer knows the name, otherwise it stays unplaced and the review page says so. Unplaced events count on their own sub-region, or, when they have none (every MATS-era seed event), on every sub-region of their move. The validator's new LOCATION rule holds a stated sub-region to the coordinates. Only accepted events of accepted moves appear.*
- [x] Time slider by year and month; filters as listed; clicking a point opens the event and its move. *One slider by month with a window selector (the month, the year, five years, everything up to) and a Play button; filters are the move's coding (claimant chips, type, domain, issue, counterpart) with the case browser's semantics. Events at one position stack into one marker with a count; a marker or a sub-region count opens a popup listing the events with date, claimant, type pills and a link to the move. A list twin of the view is one toggle away.*
- [x] Map works offline from the bundle except for the basemap tiles, which come from a free, attribution-compliant provider. *Leaflet 1.9.4 vendored (BSD-2, `web/static/vendor/leaflet`); polygons and events inline; tiles from OpenStreetMap's standard server with the required attribution (CARTO's basemaps now need an API key), re-toned by CSS in dark mode; without tiles the page still draws. A disclaimer notes that base-map names and boundaries are the provider's.*
- [x] Headless render test passes; event counts on the map equal the validator's. *`pipeline.validate.event_aggregates` is the independent count (seam 3); `data/events.json` and the markers on the rendered page are held to it, with tile requests answered by a local stub so the test is offline. Light, dark and phone viewports; time window and filters checked against the files.*
