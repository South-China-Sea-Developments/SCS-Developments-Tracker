# 08. Operations

**Depends on:** 04, 05.

**Question.** Where scheduled runs execute, what they cost, who is notified, who maintains, how failures surface.

**Settled 2026-10-15 (ticket 07):** Scheduled runs execute on **GitHub Actions** in this repository (`.github/workflows/harvest.yml`), every Monday at 06:17 UTC and on demand. The run restores the harvest state, fetches the active sources, extracts candidates, opens the review pull request, saves the state and posts reminders. The only running cost is the extractor's API calls, paid through the `ANTHROPIC_API_KEY` repository secret; each run's tokens, estimated cost and yield are appended to a run log so the cost is known per run and in total.

**Amended 2026-10-26 (ticket 14):** the maintainer cannot fund API billing, so the extraction may instead run on his Claude subscription through the Claude Code GitHub Action (secret `CLAUDE_CODE_OAUTH_TOKEN`, from `claude setup-token`): the pipeline writes the prompts as files, the action answers them with the `/harvest-extract` skill, the pipeline reads the answers. `ANTHROPIC_API_KEY`, if ever added, takes precedence. With neither secret the run fetches and opens a "waiting for extraction" issue; the session route (README, "Extraction without an API key") answers the same prompts by hand. The subscription's weekly limit is the budget on that route, so the run filters for relevance and caps the documents per run (`max_documents`, default 80; the rest are fetched again next run). GitHub Models, considered as a free route, was retired on 2026-07-30; free tiers elsewhere are too small and too changeable to build on.

**Harvest state** (which items each source has already yielded) lives on a dedicated **`harvest-state` branch** that is never merged: `state.json` plus `runs.jsonl`. A dedicated branch rather than the review pull request, because a pull request can stay open for weeks and the next run must still start where the last one stopped; rather than a direct commit to `main`, because nothing lands on `main` without a pull request (ADR 0004), and the state is operational, not data. A failed run does not save its state, so the next run retries the same items; within a successful run, documents whose extraction failed are removed from the saved state and retried too. A source that fails while others succeed does not fail the run: it shows in the run summary and in the run log's `sources_with_errors`; retiring or fixing it is a registry edit (`pipeline/sources.json`).

**Notification:** a failed run opens one issue labelled `harvest-failure` with the run summary and a link to the log; further failures comment on that issue instead of opening another; the next successful run comments and closes it. A run with no credential to extract (ticket 14) opens one issue labelled `harvest-waiting` in the same way; the next run that extracts closes issues of both kinds. A review pull request open for more than seven days gets a comment mentioning the maintainer, at most once a week. The maintainer is named in the workflow (`MAINTAINER`), one line to change on handover.

**Tokens and the merge gate.** The workflow's own token can open the review pull request, but GitHub does not run the `validate` workflow on a pull request opened that way until a person pushes to it (the coder's decision commit does). For the validator to run from the start, add a fine-grained personal access token as the `HARVEST_TOKEN` secret (this repository; contents and pull requests: read and write). The workflow pushes only `harvest/<run_id>` branches and `harvest-state`; that nothing reaches `main` without a pull request and a green validator is enforced by branch protection on `main` (require the `validate` check), which the maintainer sets in the repository settings. The state branch triggers no workflow.

**Maintainer:** Angelo M. (`Angelo-M-SCS`). Ongoing duties: review pull requests, add or retire sources in `pipeline/sources.json`, keep the secrets valid, act on failure issues.

**Dry run:** `workflow_dispatch` with `dry_run` fetches the live sources but extracts the fixture captures with the recorded responses, stops `queue open` before the push, saves no state, and prints the issue and reminder writes instead of making them, so the wiring up to the token's write side can be checked at no extractor cost.
